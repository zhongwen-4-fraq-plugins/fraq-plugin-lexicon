# Design — template-message-plugin

## Goal

- 提供词库条目的添加和删除能力。
- 每个词条包含唯一 ID、匹配方式、问题和回答模板。
- 用户消息命中问题后，解析回答中的词条并执行动作，最终发送解析后的消息。
- 词条解析不设置固定嵌套深度，使用迭代方式持续解析，直到不存在词条。

## Commands

```text
词库 添加 <词库名> <精确|模糊> 问 <内容> 答 <内容>
词库 删除 <词库名> id <词条 ID>
词库 删除 <词库名> 问 <问题内容>
```

- 删除命令建议显式使用 `id` 或 `问`，避免纯数字问题与词条 ID 冲突。
- 用户已确认两种删除方式都需要支持。
- 需要补充词库的创建、删除、列表和启停命令。

## Confirmed behavior

- 同时支持全局词库和群词库。
- 一个群可以拥有并启用多个命名词库。
- 使用 SQLite 持久化词库和词条。
- 模糊匹配表示用户消息包含问题文本。
- 词库管理权限为群主、群管理员和机器人主人。
- API 执行失败时向用户回复详细错误。
- 第一版实现 `[api.*]` 和 `[词库.*]`，不实现通用变量词条。
- `[词库.<词库名>]` 使用用户原始消息，在指定词库中执行完整匹配并继续解析回答。
- 全局词库默认不在群中生效，由群管理员手动启用；群词库创建后自动生效。
- 多词条优先级为：精确、模糊；群、全局；问题更长；ID 更小。
- API 失败时立即停止后续解析并向用户回复详细错误。

## Data model

- `lexicons`：词库 ID、名称、作用域类型、作用域 ID、创建者和时间。
- `entries`：词条 ID、所属词库、匹配方式、问题、回答模板、创建者和时间。
- 全局词库的作用域 ID 为空；群词库的作用域 ID 为群号。
- 同一作用域中的词库名称必须唯一。

## Template terms

- 词条使用平衡方括号表示，不能使用单个正则表达式解析。
- 基础语法暂定为 `[命名空间.动作.参数名=参数值]`。
- API 示例：`[api.戳一戳.user_id=123456]戳啦`。
- 词库引用示例：`[词库.公共回复]`，使用原始消息在该词库中匹配。
- 解析器先处理最内层词条，再从左到右执行同层词条。
- 动作词条可以返回文本继续参与外层解析，也可以只执行副作用并返回空文本。
- 为满足无限嵌套，不设置固定深度上限；使用重复状态检测阻止自引用死循环。
- 需要定义方括号、点号和等号出现在普通文本或参数值中时的转义规则。

## Milky nudge mapping

- 群聊戳一戳对应 `send_group_nudge`，需要 `group_id` 和 `user_id`。
- 好友戳一戳对应 `send_friend_nudge`，需要 `user_id` 和 `is_self`。
- `戳一戳` 中文动作别名需要根据当前消息场景自动选择对应 API。

## Suggested modules

- `src/index.ts`：插件入口与模块装配。
- `src/models/`：词条、匹配方式、解析结果等数据模型。
- `src/data/`：词库持久化和数据读写。
- `src/parsers/`：管理命令与嵌套词条解析。
- `src/services/`：词库增删、消息匹配和模板执行流程。
- `src/actions/`：API 动作注册表及 Milky 动作实现。
- `src/core/`：消息事件接入和整体编排。

## Safety

- 通过循环检测阻止模板直接或间接自引用。
- 限制单次解析生成的总文本长度和动作执行数量，避免资源耗尽。
- 添加、删除词条需要权限控制。
- API 参数必须经过动作处理器逐项校验，禁止任意调用未注册 API。

## Open decisions

- MVP 设计已确认，无待定实现规则。
