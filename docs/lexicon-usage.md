# 词库与词条用法

本文档介绍词库作用域、匹配规则和所有词条模板。管理命令请查看 [README 的管理命令表](../README.md#管理命令)。

## 词库作用域

- 群词库只属于创建它的群，同一个群可以创建多个群词库，创建后自动生效。
- 全局词库由机器人主人创建，每个群需要由群主、管理员或机器人主人手动启用。
- 私聊使用全部全局词库。
- 同名词库默认优先解析群词库，可使用 `群:<名称>` 或 `全局:<名称>` 明确指定。

## 匹配顺序

多个词条同时命中时依次比较：

1. 精确匹配优先于模糊匹配。
2. 群词库优先于全局词库。
3. 问题文本更长的词条优先。
4. ID 更小的词条优先。

模糊匹配表示用户消息中包含词条的问题文本。

## 词条速查

以下词条按开头分组，同一表格内按词条格式从短到长排列。尖括号中的内容需要替换为实际值；API 表只列通用格式，不展开具体端点。

### `逻辑` 开头

| 词条 | 作用 |
| --- | --- |
| `[逻辑.判断]` | 开始条件块，后面必须紧跟条件词条 |
| `[逻辑.否则]` | 设置条件块的默认分支 |
| `[逻辑.否则判断]` | 设置条件块的后续条件分支，后面必须紧跟条件词条 |
| `[逻辑.判断.结束]` | 结束条件块 |
| `[逻辑.计次循环尾]` | 结束最近一层计次循环 |
| `[逻辑.休眠.<秒数>]` | 等待指定秒数后继续执行回答 |
| `[逻辑.计次循环.<次数>]` | 开始执行指定次数的计次循环 |
| `[逻辑.等于.<值1>.<值2>]` | 精确判断两个值是否相同，只能用于条件块 |
| `[逻辑.不等于.<值1>.<值2>]` | 精确判断两个值是否不同，只能用于条件块 |
| `[逻辑.请求用户输入.<提示消息>]` | 提示并等待同一用户的下一条消息 |
| `[逻辑.in.<目标>.<候选1>...]` | 判断目标是否等于任意候选，只能用于条件块 |
| `[逻辑.or.<参数1>.<参数2>...]` | 文本模式返回首个可用参数；条件模式只接受 `true` 和 `false` |
| `[逻辑.and.<参数1>.<参数2>...]` | 文本模式拼接全部参数；条件模式只接受 `true` 和 `false` |
| `[逻辑.notin.<目标>.<候选1>...]` | 判断目标是否不等于全部候选，只能用于条件块 |
| `[逻辑.请求用户输入.<提示消息>.<超时时间=秒>]` | 使用本次指定的超时时间等待用户输入 |
| `[逻辑.请求用户输入.<提示消息>.<超时提示=文本>]` | 使用本次指定的超时提示等待用户输入 |
| `[逻辑.请求用户输入.<提示消息>.<超时时间=秒>.<超时提示=文本>]` | 同时指定等待时间和超时提示 |

### `循环` 开头

| 词条 | 作用 |
| --- | --- |
| `[循环.退出]` | 保留当前迭代已生成的内容并结束最近一层循环 |
| `[循环.跳过]` | 保留当前迭代已生成的内容并进入下一次迭代 |

### `event` 开头

| 词条 | 作用 |
| --- | --- |
| `[event.<事件名>]` | 匹配或确认当前 Milky 事件名称 |
| `[event.<字段路径>]` | 读取当前事件对象中的字段或数组下标 |

### `消息` 开头

| 词条 | 作用 |
| --- | --- |
| `[消息.构建.text.<内容>]` | 构建一个可用于 API 参数的文本消息段 |
| `[消息.读取.<消息段类型>.<字段路径>]` | 读取当前消息中首个指定类型消息段的字段 |

### `文件` 开头

| 词条 | 作用 |
| --- | --- |
| `[文件.打开.<文件名>.<操作方式>]` | 在项目的 `data` 目录内按指定方式打开文件，并返回 UTF-8 文本内容 |

### `api` 开头

| 词条 | 作用 |
| --- | --- |
| `[api.<英文 API 端点>]` | 调用不需要显式参数或可从事件补全参数的 API |
| `[api.<英文 API 端点>.<参数名>=<参数值>...]` | 使用一个或多个显式参数调用 API |

### `词库` 开头

| 词条 | 作用 |
| --- | --- |
| `[词库.拒绝执行]` | 终止当前回答并跳过后面的文本与词条 |
| `[词库.<词库名>]` | 使用原始消息在指定词库中继续匹配和执行 |

### `变量` 开头

| 词条 | 作用 |
| --- | --- |
| `[变量.创建.<变量名>]` | 创建值为空文本的变量 |
| `[变量.读取.<变量名>]` | 读取已创建变量的内容 |
| `[变量.创建.<变量名>=<变量值>]` | 创建变量并保存指定内容 |

### `json` 开头

| 词条 | 作用 |
| --- | --- |
| `[json.取值.<变量名>.<字段路径>]` | 从变量保存的 JSON 中读取对象字段或数组下标 |

## 词条详细说明

### 逻辑词条

条件外的逻辑词条只执行文本操作：

```text
[逻辑.or.文本1.文本2]
[逻辑.and.文本1.文本2]
```

- `or` 按参数顺序返回第一个非空参数。
- `and` 按顺序拼接全部参数。
- `in`、`notin`、`等于` 和 `不等于` 只能用于条件块，不能作为普通文本词条执行。
- 文本模式下，`or` 会跳过空文本、未创建变量和当前消息中不存在的字段，优先返回第一个可用候选；第一个不可用时继续尝试后续候选，全部候选都不可用时返回错误。

例如，优先使用变量内容，没有内容时使用备用文本：

```text
[逻辑.or.[变量.读取.首选内容].备用文本]
[逻辑.or.[消息.读取.mention.user_id].未艾特用户]
```

条件块中的 `or` 仍然只执行布尔逻辑，不会把缺失变量当作 `false`。

### 拒绝继续执行

使用 `[词库.拒绝执行]` 立即终止当前问答的回答解析：该词条之前已经生成的文本和已执行的 API 会保留，之后的文本和词条都不会输出或执行。它只影响当前一次回答，下一条消息仍会正常匹配和执行。

```text
前置内容[词库.拒绝执行]这段不输出[api.some_action]
```

上面的模板只输出“前置内容”，`api.some_action` 不会调用。该词条不能用于逻辑条件或计次循环次数；`拒绝执行` 也是保留名称，不能作为普通词库名引用。

### 休眠

使用 `[逻辑.休眠.<秒数>]` 在回答执行过程中等待指定秒数，然后继续解析后面的内容：

```text
开始[逻辑.休眠.2]结束
开始[逻辑.休眠.0.5]结束
```

休眠时间按秒计算，支持小数；必须是正数，且不能超过 Node.js 定时器上限。休眠只允许用于回答文本，不能用于问题、逻辑条件或计次循环次数。

条件块以 `[逻辑.判断]` 开始，以 `[逻辑.判断.结束]` 结束；`否则判断` 和 `否则` 都可以省略：

```text
[逻辑.判断][逻辑.or.true.false]条件成立
[逻辑.否则判断][逻辑.等于.目标.目标]次级条件成立
[逻辑.否则]全部条件不成立
[逻辑.判断.结束]
```

- `[逻辑.判断]` 和 `[逻辑.否则判断]` 后必须紧跟一个 `or`、`and`、`in`、`notin`、`等于` 或 `不等于` 条件词条。
- 条件中的 `or` 和 `and` 始终执行布尔逻辑，不再根据参数内容自动判断模式。
- 条件中的 `in` 判断第一个参数是否精确等于后续任意候选。
- 条件中的 `notin` 判断第一个参数是否与后续全部候选都不相等。
- 条件中的 `等于` 和 `不等于` 必须接收两个非空参数，并按原文本进行精确比较，不会忽略大小写或前后空格。
- 条件中的 `逻辑.or` 和 `逻辑.and` 只接受完全匹配的小写 `true` 和 `false`，不接受大小写变体、前后空格或其他布尔别名。
- 条件、分支内容和整个条件块都支持变量、事件、消息段、其他逻辑词条以及无限嵌套。
- 未选中的分支不会执行，其中的 API 和变量操作也不会产生副作用。

使用 `[逻辑.请求用户输入.<提示消息>.<超时时间=秒>.<超时提示=文本>]` 可以发送指定提示，再等待同一用户在同一群聊或私聊中的下一条消息。`超时时间` 和 `超时提示` 都可以省略：

```text
词库 添加 精确 问 登记名字 答 [变量.创建.名字=[逻辑.请求用户输入.请输入名字]]你好，[变量.读取.名字]！
词库 添加 精确 问 临时登记 答 [逻辑.请求用户输入.请输入内容.超时时间=30.超时提示=会话超时]
```

- 命中词条时只发送请求词条中的提示消息，不会提前发送请求词条之前的回答内容。
- 用户回复后，输入内容会替换请求词条并继续解析，最终回答会一次性发送。
- 提示消息和后续内容都支持变量、事件、消息段、API、词库和逻辑词条嵌套。
- 多个请求词条会按出现顺序依次等待，已选中的条件分支中也可以使用请求词条。
- 用户输入会作为普通文本处理，不会被当成 API 或其他模板执行。
- 等待期间，词库管理命令优先执行且不会被消费；其他下一条消息会作为输入，不再触发其他词库。
- `超时时间` 使用秒数，并覆盖本次请求的默认等待时间；省略时默认等待 30 秒，也可以通过插件配置 `userInputTimeoutMs` 修改全局默认值。
- `超时提示` 省略时默认发送“会话超时”；超时提示支持变量、事件、消息段、API、词库和逻辑词条嵌套。
- 超时后只发送超时提示并终止本次回答，不会再追加“词条执行失败”；无提示消息的语法不支持，请求词条也不能放在问题或逻辑条件参数中。

### 计次循环

使用 `[逻辑.计次循环.<次数>]` 开始循环，使用 `[逻辑.计次循环尾]` 结束：

```text
[逻辑.计次循环.3]哈[逻辑.计次循环尾]
[变量.创建.N=3][逻辑.计次循环.[变量.读取.N]]哈[逻辑.计次循环尾]
```

上面两个模板都输出 `哈哈哈`。次数会在进入循环前解析一次，可以是固定数字，也可以使用变量或其他嵌套词条生成。

```text
[逻辑.计次循环.3]A[循环.跳过]B[逻辑.计次循环尾]
[逻辑.计次循环.3]A[循环.退出]B[逻辑.计次循环尾]
```

- `[循环.跳过]` 保留当前迭代中已生成的内容，跳过后续内容并进入下一次迭代；第一个示例输出 `AAA`。
- `[循环.退出]` 保留当前迭代中已生成的内容，然后结束最近一层循环；第二个示例输出 `A`。
- 循环支持任意嵌套；退出和跳过只影响最近一层循环。
- 退出和跳过可以放在条件分支中；未选中的分支不会执行循环控制。
- 循环可在问题和回答中使用，循环内可继续使用变量、事件、消息段、API、词库、条件和用户输入词条。
- 次数必须是 `0..10000` 之间的整数；`0` 次不执行循环内容。
- `[循环.退出]` 和 `[循环.跳过]` 不能在循环外或循环次数表达式中使用。

### 事件词条

将事件模板作为词条的问题，即可在对应 Milky 事件发生时执行回答：

```text
词库 添加 精确 问 [event.group_nudge] 答 收到来自 [event.data.sender_id] 的戳一戳
词库 添加 精确 问 [event.friend_file_upload] 答 收到文件 [event.data.file_name]
```

插件监听 Fraq 提供的全部 21 个 Milky 事件。群事件匹配当前群词库和已启用的全局词库；好友事件及没有群号的事件匹配全局词库。回答产生文本时会发送到当前群或好友会话；没有可发送会话的事件仍会执行回答中的 API 词条。

回答中可以使用 `[event.<字段路径>]` 读取完整事件对象，支持对象字段和数组下标：

```text
[event.event_type]
[event.time]
[event.self_id]
[event.data.group_id]
[event.data.segments.0.data.text]
[变量.创建.QQ=[event.data.sender_id]][api.send_group_nudge.user_id=[变量.读取.QQ]]
```

事件字段可以进入变量、API 参数和其他嵌套词条。字符串与 JSON 会自动转义模板控制字符；字段不存在时会返回明确错误。

事件词条、消息段词条和变量词条在问题与回答中都可使用：

```text
词库 添加 精确 问 [event.message_receive][变量.创建.Q=戳我][变量.读取.Q] 答 [event.message_receive]收到
词库 添加 精确 问 [变量.创建.QQ=[event.data.sender_id]][变量.读取.QQ] 答 你的 QQ 是 [event.data.sender_id]
```

- 问题中的 `[event.<事件名>]` 是事件条件，只在当前事件名称相同时匹配，并且自身不参与文本比较。
- 回答中的 `[event.<事件名>]` 是事件条件，匹配时不输出文本，事件名称不同时返回明确错误。
- 问题中的事件字段会先转换为当前字段值，再按照精确或模糊模式与消息文本比较。
- 问题中的变量拥有独立作用域，可以创建、读取并嵌套事件字段。
- 为避免匹配消息时产生副作用，问题中的 API 和词库词条保持字面量，不会执行。

### 消息段词条

```text
[消息.读取.<消息段类型>.<字段路径>]
[消息.读取.mention.user_id]
[消息.读取.reply.sender_id]
[消息.读取.reply.segments.0.data.text]
```

`消息.读取` 会读取当前消息中第一个指定类型的 IncomingSegment，字段路径从消息段的 `data` 开始，因此不需要再写一层 `data`。对象字段和数组下标都可继续嵌套读取；消息段或字段不存在时会返回明确错误。

消息段值可以进入变量、问题和 API 参数。例如发送 `getinfo` 并艾特群成员时：

```text
词库 添加 精确 问 getinfo 答 [api.get_group_member_info.user_id=[消息.读取.mention.user_id]]
```

使用 `消息.构建.text.<内容>` 构建文本消息段，结果可以直接作为 API 的 `message` 参数，也可以继续嵌套变量和其他词条：

```text
[消息.构建.text.内容]
[变量.创建.A=动态内容][消息.构建.text.[变量.读取.A]]
[api.send_group_message.message=[消息.构建.text.内容]]
```

当前仅支持构建 `text` 消息段；其他消息段类型会返回明确错误。

完整消息段类型和字段请参考 [Milky IncomingSegment](https://milky.ntqqrev.org/struct/IncomingSegment)。

### 文件词条

使用下面的词条在插件配置的 `dataPath` 目录内打开文件，并返回文件当前的 UTF-8 文本内容。未配置时使用项目工作目录的 `data` 目录：

```text
[文件.打开.<文件名>.<操作方式>]
[文件.打开.notes\.txt.读取]
[文件.打开.config/settings\.json.读写]
```

文件名必须是相对于 `dataPath` 目录的路径。不能使用绝对路径或 `..` 离开该目录，符号链接也不能绕过该限制。路径推荐使用 `/` 分隔；文件名中的点号必须写成 `\.`，例如 `notes\.txt`。`dataPath` 的配置方式请参考 README 安装示例。

中文操作方式与 Node.js `fs.open` 标志一一对应：

| 操作方式 | Node.js 标志 | 行为 |
| --- | --- | --- |
| `读取` | `r` | 读取已有文件，文件不存在时报错 |
| `读写` | `r+` | 读写已有文件，文件不存在时报错 |
| `同步读取` | `rs` | 以同步 I/O 方式读取已有文件 |
| `同步读写` | `rs+` | 以同步 I/O 方式读写已有文件 |
| `覆盖写入` | `w` | 创建文件；文件已存在时清空内容 |
| `独占覆盖写入` | `wx` | 仅在文件不存在时创建，已存在时报错 |
| `覆盖读写` | `w+` | 创建并读写文件；文件已存在时清空内容 |
| `独占覆盖读写` | `wx+` | 仅在文件不存在时创建并读写，已存在时报错 |
| `追加写入` | `a` | 创建文件或从文件末尾追加打开 |
| `独占追加写入` | `ax` | 仅在文件不存在时创建并追加打开，已存在时报错 |
| `追加读写` | `a+` | 创建文件或以读取和末尾追加方式打开 |
| `独占追加读写` | `ax+` | 仅在文件不存在时创建并读写追加，已存在时报错 |
| `同步追加写入` | `as` | 以同步 I/O 方式创建或追加打开文件 |
| `同步追加读写` | `as+` | 以同步 I/O 方式创建或读写追加文件 |

该词条返回文件内容，不返回可继续操作的文件句柄。因为语法中没有“写入内容”参数，写入类操作方式只执行 `fs.open` 自身的创建、截断或追加打开行为；它们不会向文件写入额外文本。文件词条只能用于回答，不能用于问题匹配。

### API 词条

```text
[api.<英文 API 端点>.<参数名>=<参数值>]
[api.send_group_nudge]
[api.send_group_nudge.user_id=123456789]
[api.get_group_member_info.user_id=123456789]
```

插件支持当前 Milky/Fraq 提供的全部 65 个英文 API 端点。用户显式填写的参数优先；未填写时会先读取事件 `data` 中的同名字段，再按端点需要补充：

- `user_id`：第一个被艾特的 QQ、被回复消息的发送者、事件中的 `user_id`、`sender_id`、`operator_id`、`initiator_id`，最后是当前发送者。
- 参数名必须使用 Milky 协议定义的英文名称，不再接受 `qq` 等别名。参数名错误时会提示建议名称或可用参数列表。
- `group_id`：当前群号；群消息撤回等事件会根据 `message_scene=group` 将 `peer_id` 转为群号；有效范围为 `10001..4294967295`。
- `message_scene`、`peer_id`：当前消息场景和会话 ID。
- `message_seq`、`start_message_seq`：被回复消息的序列号，否则使用当前消息序列号；`message_seq` 有效范围为 `0..9007199254740991`。
- `message`、`content`：被回复消息的消息段，否则使用当前消息的消息段。
- `resource_id`、`uri`、`image_uri`、`file_uri`：回复或当前消息中的首个图片、语音或视频资源。
- `file_id`、`file_hash`、`file_name`、`forward_id`：回复或当前消息中的文件、合并转发数据。
- `notification_type`：根据 `group_join_request` 或 `group_invited_join_request` 事件自动生成。
- `reaction`：群消息反应事件会自动将 `face_id` 转为 API 使用的 `reaction`。
- `is_self_send`：好友文件事件会自动继承事件中的 `is_self`。
- `no_cache=false`、`is_filtered=false`、`is_self=false`、`is_self_send=false`、`limit=20`、`count=1`。

事件自身提供的参数不会被上述默认值覆盖。调用前会检查必填参数、`group_id` 与 `message_seq` 范围，以及 `message_scene`、`notification_type`、`reaction_type` 等枚举参数，并直接返回可读错误；显式参数和事件自动参数使用相同校验。

常见语法错误会在调用 API 之前直接返回：

- `[api.get_user_name]`：提示没有 `get_user_name` 这个 Milky API。
- `[api.get_user_profile.qq=xxx]`：提示参数名 `qq` 应当是 `user_id`。
- `[api.get_cookies]`：提示缺少必填参数 `domain`。

消息参数可以直接填写文本，也可以填写消息段 JSON：

```text
[变量.创建.result=[api.send_group_message.message=Hello]][变量.读取.result]
[变量.创建.target=123456789][变量.创建.result=[api.send_group_nudge.user_id=[变量.读取.target]]]
```

API 返回空对象时不输出文本；其他返回值会序列化为 JSON，并可通过变量继续参与嵌套解析。完整端点定义位于 `src/data/milky-api-definitions.ts`。

本插件已适配 Fraq 1.1 暴露的全部 65 个 Milky API，不兼容 Fraq 0.x，具体参数请参考 [Milky 协议 API](https://milky.ntqqrev.org/api/system)。

### 词库词条

```text
[词库.<词库名>]
```

词库词条会使用用户的原始消息，在指定词库中执行完整匹配，并继续解析命中的回答：

```text
词库 添加 入口 精确 问 戳我 答 [词库.动作库]
词库 添加 动作库 精确 问 戳我 答 [变量.创建.result=[api.send_group_nudge]]戳啦
```

解析器不设置固定嵌套深度，使用迭代方式持续解析；检测到直接或间接循环引用时会停止并回复详细错误。

### 变量词条

```text
[变量.创建.A]
[变量.创建.A=变量内容]
[变量.读取.A]
```

同一次词条命中中，问题创建的变量可以在回答中读取；通过 `[词库.<词库名>]` 命中的嵌套词条也会把问题变量传递给后续回答。每条新消息或新事件都会创建独立变量作用域。变量内容可以继续包含词条，读取变量后会继续参与嵌套解析；回答中读取未创建变量会返回错误，问题中读取未创建变量则视为不匹配。

使用 JSON 取值词条可以解析变量中的 JSON，并按字段路径读取对象字段或数组下标：

```text
[json.取值.<变量名>.<字段路径>]
[变量.创建.响应={"data":{"user":{"name":"小明"}}}][json.取值.响应.data.user.name]
[变量.创建.响应=[api.get_group_info]][json.取值.响应.group_name]
[变量.创建.字段=name][json.取值.响应.data.user.[变量.读取.字段]]
```

JSON 取值词条支持问题和回答、变量及其他词条的无限嵌套。读取对象或数组时会输出 JSON 文本；变量未创建、内容不是有效 JSON 或字段不存在时会返回明确错误。

需要输出字面量方括号、点号或等号时，可以使用反斜杠转义，例如 `\[普通文本\]`。
